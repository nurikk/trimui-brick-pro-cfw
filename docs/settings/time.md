# Time & Locale settings-domain contract

This is a clean-room, no-device MVP contract for a future generic registry/menu generator. It supplies semantic field requirements and synthetic defaults; it is not a global settings schema, persistence format, translation engine, network/NTP implementation, RTC/HAL contract, or device claim.

## Scope and transaction rules

- `global` fields are whole-system preferences or clock setpoints, not per-user values. A writable edit is staged; the committed value changes only after **Confirm** validates the complete candidate atomically. A failed candidate never persists a partial change. **Cancel** discards the pending candidate and preserves committed values.
- **Reset** restores the documented writable defaults as one confirmed atomic change. Read-only runtime fields are not reset by the menu.
- `runtime/read-only` fields describe observed or explicitly unavailable runtime state. They are never editable and must not be turned into success claims by a generator.
- Values and status in this document are semantic only. Actual storage, clock application, network synchronization, and hardware access are out of scope.

## Finite options

- `timezone`: exactly `UTC`, `America/New_York`, `Europe/London`, or `Asia/Tokyo`. These are deliberately finite IANA-like identifiers, not free-form input and not a promise of full time-zone database coverage.
- `clockFormat`: exactly `12h` or `24h`.
- `language`: exactly `en-US`, `es-ES`, `fr-FR`, or `de-DE`. This is a finite language placeholder, not a translation engine.
- `automaticNetworkTime` requires explicit capability `network_time_sync=true`; capability must never be inferred from a network probe or hardware assumption.
- `manualDate` is strict ISO `YYYY-MM-DD`, year `2000`–`2099`, with a valid calendar day. `manualTime` is strict 24-hour `HH:MM`, hour `00`–`23`, minute `00`–`59`; seconds and offsets are not accepted.
