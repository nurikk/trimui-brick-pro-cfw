# Media cache v1

The media cache consumes only a typed `scrape-result/v1` reference: an opaque content ID, one of `box-art`, `screenshot`, `title-screen`, or `logo`, an HTTPS URL, optional bounded region/language, and an opaque provider value. It does not identify games, title-match, authenticate, read credentials, or own a scraper client.

## Acquisition boundary

`Transport` is a narrow port. The crate never constructs an HTTP client and never performs network or DNS I/O. A transport receives a `ValidatedUrl` and returns a status, declared MIME, optional redirect location, and a deadline-aware body reader. A future real transport must validate every resolved and connected address as public before opening a connection; fixture transport has no DNS or network path.

Before every fetch, including every redirect, the URL validator requires absolute ASCII HTTPS, bounded authority/path, no userinfo, no malformed port, no localhost, and no private, loopback, link-local, unspecified, multicast, or other non-public literal IP. Redirects are individually validated and bounded to five. The transfer streams into a caller-selected, external temporary area with a 32 MiB total limit and deadline. The temporary root is absolute, non-symlinked, outside the derived cache, and rejected if it intersects protected trees. Collision-safe names include a private identity derived from the canonical cache root, so one cache never cleans another cache's files. Partial files are removed on every error. Restart cleanup removes only matching files older than twice the configured transfer deadline; files at or below that conservative threshold, including fresh or possibly active files, are retained as harmless temporary state. Transfer files never enter the object, index, or provenance trees.

Only `image/png` and `image/jpeg` are accepted, and the declared MIME must agree with the decoded signature. PNG decoding uses the locked `png` dependency with explicit 8,192 x 8,192, 16-million-pixel, 64 MiB decoded-memory, decoder-allocation, and configured decode-time limits. Animated PNG, indexed/unknown color, malformed, corrupt, and oversized images fail closed. JPEG v1 is baseline, 8-bit, non-progressive, grayscale or YCbCr, with bounded dimensions and the same decode-time budget; unsupported sampling forms and malformed entropy fail closed. The fixture decoder supports the baseline sampling forms needed by v1 fixtures. Valid EXIF orientation values 1–8 are normalized before resizing; malformed EXIF, invalid orientation values, and unsupported APP1 payloads fail closed. JPEGs without EXIF orientation use stored orientation. PNG has no orientation metadata in this pipeline.

## Derivation

Four named profiles fit within 1024x768 without upscaling: `cover` crops the centered fit to the target aspect ratio, while `screenshot-preview`, `title-screen`, and `transparent-logo` preserve the fit aspect ratio. Logos retain alpha; other profiles are composited to opaque output. Every result is encoded as deterministic PNG v1, with only the selected color type and image data, so metadata and source encoding differences do not affect the object bytes.

## Cache and safety

Objects are SHA-256-addressed under `objects/<shard>/<digest>.png`. The opaque content-ID index is separate from per-object private provenance under `metadata`. Provenance contains provider, source URL SHA-256, media kind, output dimensions, byte size, object digest, and `fetched-validated` status; it is never public output. Publication writes a uniquely named, synced temporary file and performs a no-replace atomic rename, validating an existing winner before convergence; metadata and index records are likewise validated rather than overwritten. Parent directories are synced. A process-local publication lock plus digest verification makes same-object fixture writers converge and deduplicates byte-identical output.

Quota/LRU scans only the derived `objects` tree. Eviction removes the associated private provenance and only index entries that point at the evicted object. It rejects absolute-path violations, protected-tree intersections, and symlinks. It cannot recurse into ROMs, saves, states, themes, credentials, or external metadata. Public journey output contains only aggregate counts and fixed status text; it never prints URLs, URL hashes, provider values, object digests, local paths, image bytes, or ROM identifiers.

## Generated evidence

`media-cache-journey` generates PNG and JPEG inputs in memory and uses a deterministic fixture transport. It checks repeatable bytes and dedupe, all profiles and alpha, JPEG EXIF orientation normalization, MIME/content and dimension failures, HTTP/private/userinfo URLs, unsafe and exhausted redirects, interrupted transfer, external stale-temporary restart, two cache identities sharing one temporary root, concurrent convergence, quota-only deletion, protected fixture preservation, and sanitized output. `fixtures/media-cache/jpeg.hex` is compact generated synthetic JPEG source data, not artwork or firmware. This is host/static evidence only; it is not a device, filesystem power-loss, stock ABI/loader/runtime, or hardware-compatibility claim.
