# MVP Input & Controller settings contract

This is a domain-scoped semantic contract for a future settings registry. It is not a registry schema or descriptor format. Capability and operation values are metadata contracts only; they do not describe device observations or implement I/O.

`profile` values are editable settings. Edits are staged until an explicit confirm; cancel discards the draft. `session` values describe transient action/status state. An unavailable capability is fail-closed: the surface is hidden and an invocation is rejected as `unsupported`.

## Confirmation and status vocabulary

- A pending draft has separate `effective` and `staged` values; readers continue to see `effective` until confirm.
- Confirm commits only valid staged values. Cancel removes the draft without changing effective values.
- `unsupported`, `invalid`, `inactive`, and `failed` are explicit outcomes. They are not silently converted to defaults or success.
- Action and status IDs are semantic metadata only. Pairing, calibration, testing, and rumble behavior require a future implementation behind these contracts.
